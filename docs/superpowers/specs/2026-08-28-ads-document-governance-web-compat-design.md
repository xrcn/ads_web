# ADS 文档治理前端兼容设计

## 状态

- 本文是 `ads_server/docs/superpowers/specs/2026-08-28-ads-document-governance-design.md` 的前端仓库配套设计。
- 设计范围已于 2026-08-28 在对话中确认，等待用户复核后引用后端主设计对应的一份权威实施计划；本仓不创建重复计划。
- 本设计不授权 commit、发布、业务代码修改或生产操作。

## 背景

父级 `E:\ads\AGENTS.md` 将缩减为仓库路由和公共安全边界。当前 `ads_web/AGENTS.md` 声明自己只是父级规范的“增量规范”，因此不能在父级缩减后保持原文不变，否则会丢失任务范围、Git 保护和完成边界。

## 目标

- 让 `ads_web/AGENTS.md` 在精简父级下仍能独立约束前端任务。
- 保留现有 Vue、浏览器取证、dotenv 和微信 API 可视化控制台规则，并把 build 的必要触发条件写清楚。
- 删除 `ads_web/memory.md` 中的执行规范，只保留已验证前端经验。
- 不把本次任务扩大为完整前端文档体系重构。

## 修改范围

### `ads_web/AGENTS.md`

- 将标题从“前端增量规范”调整为完整前端项目入口。
- 保留现有七个主题的有效规则。
- 补入单仓 scope、任务风险、dirty worktree、未授权 Git 写操作和完成报告的最小边界。
- 明确单纯后端任务不需要检查本仓；跨仓任务才同时应用两个子仓入口。
- 前端验证命令只在本文件定义，不复制到父级。
- 单文件低风险任务默认不创建设计、计划，不做独立 review，不扫描或更新规则；只在命中明确触发条件时升级。
- 实施前先检查目标实现、直接使用方和已有验证；只有发现状态共享、权限、配置、API 契约或构建影响时才扩展检查。证据充分后立即停止，已满足时不重复实现，部分满足时只补真实缺口。
- 标准复杂前端任务只维护一份简短方案，闭包末运行一次必要 build 并由主 Agent 自检；多文件、耗时或跨仓本身不触发独立 review。
- 只有权限、安全、生产发布、无法证明等价的业务契约变化、核心职责重构、用户明确要求或主 Agent 无法确认的高风险问题才触发一次聚焦 review；普通 finding 修复后不默认 re-review。
- 同一适用文档和验证结果在输入未变化时复用，不重复读取或执行；中间状态只在范围、结果、风险或 blocker 变化时报告。

### 前端低风险验证边界

当前 `package.json` 只有 `dev`、`build` 和会改写源码的 `lint-fix`，没有 test 或独立 typecheck script。因此：

- 纯 Markdown、`README.md` 和 `CHANGELOG.md` 修改不运行 `npm run build`。
- `public/wechat-visual-console` 的独立静态资源只执行受影响资源的语法、专用 verifier 和必要浏览器验证，不因其位于前端仓库而运行 Vue 主站 build。
- `src` 下 Vue、TypeScript、API、store、样式或 Vite 构建配置发生变化时，在闭包末运行一次 `npm run build`。在当前工具链下它属于前端最小编译验证，不按主设计中的后端 full validation 理解，也不得在同一输入下重复执行。
- 将来项目新增可靠的 test 或独立 typecheck script 后，应基于真实覆盖重新收窄验证矩阵，不能永久沿用“所有 `src` 变更都 build”。

### `ads_web/memory.md`

删除以下规范性内容：

- 必须同时读取根级与子仓 `AGENTS.md`。
- 跨仓设计和计划必须分别落在两个仓库。

保留模板展示、上传组件和 Token 刷新等已验证技术经验。

### 后续规则演进

- 只有任务过程中已经识别出新的、可跨任务复用的已验证事实时，才处理规则候选；不得为了寻找候选额外扫描文档。
- 首次确认的前端根因、浏览器行为、兼容边界和规避方式写入 `memory.md`。
- 只有用户确认长期适用、在至少两个独立任务中重复验证，或涉及明确高风险边界时，才晋升为前端长期规则。
- 模块专属经验保留在模块文档或更深层规则中，不追加到父级 `E:\ads\AGENTS.md`。
- 更新前先搜索并修订同主题旧条目；没有新事实时不修改文档。
- 自动更新不得未经用户明确确认降低 TDD、dirty worktree、业务契约、权限、多租户、安全、发布或生产门禁。
- 发布、权限、生产操作和 Git 历史等最高级授权不得由 Codex 自行扩大。

## 非目标

- 不创建前端 `project-engineering-standard.md` 或 `ai-execution-policy.md`。
- 不修改 `README.md`、`CHANGELOG.md`、业务代码、测试、依赖和配置。
- 不运行 npm build、浏览器检查或生产验证。

## 验证

- 检查 `ads_web/AGENTS.md` 不再依赖父级已删除的正文。
- 检查前端 build、浏览器和静态控制台规则没有在父级重复。
- 检查纯文档、独立静态控制台和 `src` 代码分别命中正确的验证路径。
- 检查 memory 不再包含执行规范。
- 检查规则演进条款不会把普通前端经验提升到父级公共规范。
- 使用 `git ls-files --others --exclude-standard` 枚举新增文件并直接检查结构、尾随空白和冲突标记，避免依赖不覆盖 untracked 文件的 `git diff --check`。
- 运行 `git diff --check`、`git diff --name-status` 和最终 `git status --short --branch`。

## 验收标准

- 父级缩减后，前端任务的关键保护和验证规则没有丢失。
- 前端规则只影响 `ads_web` 或明确的跨仓任务。
- 本批没有业务代码、构建产物、暂存区或生产状态变化。
