# ADS 管理后台移动端响应式与卡片列表设计

## 1. 目标

修复 ADS 管理后台在手机竖屏下的内容缺失、遮挡和不可读问题，并将用户确认的 B 方案作为列表页统一基线：桌面继续使用现有表格，移动端改用卡片列表，所有字段和操作仍可访问。

目标宽度为 320px 至 768px，重点验收 390×844 与 430×932；大于 768px 的桌面布局和业务行为保持不变。

## 2. 范围

### 2.1 特殊页面

- 登录页：恢复移动端 Logo、版权和公司名称，消除全屏空白与层级遮挡。
- 微信 API 可视化控制台：移动端将固定左侧目录改为可横向滚动的顶部目录，主内容占满可用宽度。
- 机器人配置：顶部操作区、群选择器、页签、描述区、抽屉及内部列表适配移动端。
- 字典管理：移动端将字典类型树与字典数据由左右双栏改为上下排列。
- 用户管理：移动端将部门树与用户数据由左右双栏改为上下排列。

### 2.2 移动端卡片列表页面

业务页面：

- 主播列表 `/anchor/manage`
- 微信消息监听 `/wechat/message`
- 微信群 `/wechat/group`
- 消息模板 `/wechat/template`
- 微信账号 `/wechat/account`
- 主播麦序时长 `/wechat/scheduleDuration`
- 麦序明细 `/anchor/mic`
- 运行监控中的机器人状态与健康事件列表 `/wechat/monitor`

系统页面：

- 参数管理 `/system/config/list`
- 菜单管理 `/system/auth/menuList`
- 角色管理 `/system/auth/roleList`
- 部门管理 `/system/auth/deptList`
- 岗位管理 `/system/auth/postList`
- 用户管理 `/system/auth/user/list`
- 登录日志 `/system/monitor/loginLog`
- 操作日志 `/system/monitor/operLog`
- 在线用户 `/system/monitor/userOnlie`
- 代码生成 `/system/tools/gen`
- 定时任务 `/system/sysJob/list`
- 字典数据 `/system/dict/type/list`

### 2.3 明确不在本批范围

- 四个 API 调试空白页：获取微信群列表、获取群/好友详细信息、获取群/好友简要信息、发送文字消息。
- API 文档 iframe 的 `localhost:8808` 地址错误。
- 后端 API、数据库、权限、菜单数据、命令规则和业务状态变化。
- 生产发布、远端写入和真实业务验收。

上述两个全尺寸功能故障需要单独确认组件契约、目标地址和发布风险，不能混入响应式改造。

## 3. 已确认方案

### 3.1 响应式边界

- `max-width: 768px`：移动端模式。
- `min-width: 769px`：保留当前桌面模式。
- 页面不得产生全局横向滚动；长 wxid、appId、URL、时间和消息文本使用换行或展开区承载。
- 可点击目标保持约 44px 高，关键操作不依赖 hover。

### 3.2 桌面表格与移动卡片并存

每个列表页面继续使用同一份响应式数据、loading、empty、分页和权限状态：

- 桌面端渲染现有 `el-table`，不改变列、固定列和交互。
- 移动端渲染卡片列表，不在同一时刻显示桌面表格。
- 卡片模板直接调用页面现有格式化函数和操作 handler，不复制 API 请求或业务判断。
- 分页器位于桌面表格和移动卡片之外，由两种视图共用。

新增一个只负责容器状态的共享组件 `MobileRecordList`：

- 输入：`data`、`loading`、`rowKey`。
- 输出：逐行 scoped slot、统一 empty 状态和可选 loading 状态。
- 不负责字段定义、权限判断、按钮行为或业务格式化。

字段和操作由各页面现有代码提供，避免建立第二套业务真相。

### 3.3 卡片信息层级

卡片采用用户确认的草图结构：

1. 标题区：业务主键或名称、最重要状态。
2. 关键字段区：默认展示 3 至 5 个最常用字段。
3. 完整信息区：默认折叠，展开后展示原表格剩余字段；不隐藏数据。
4. 操作区：一个主操作、一个次操作和“更多”；危险操作放入“更多”并保留现有确认流程。

不同页面只改变字段映射，不改变这四层结构。桌面端不使用卡片。

### 3.4 筛选区与分页

- 移动端筛选区默认显示当前筛选摘要，可展开完整表单。
- 展开后字段单列排列，输入框和选择器宽度为 `100%`。
- 查询与重置沿用现有 handler；不改变默认筛选值和请求参数。
- 分页保持原有 page/pageSize 语义；手机端隐藏无必要的跳页控件，只保留总数、页大小和上一页/下一页。

## 4. 特殊页面设计

### 4.1 登录页

- `.login-container` 使用 `min-height: 100dvh`，允许内容自然增长。
- Logo 在移动端缩小而不是隐藏。
- 登录表单维持单列，卡片不再强制 `height: 100%`。
- footer 进入正常文档流或取得明确高于背景层的层级，确保无需滚动即可看到；极矮屏允许纵向滚动。

### 4.2 微信 API 可视化控制台

- iframe 父页面继续占满主内容区，不改变 same-origin 或 API 代理逻辑。
- 静态控制台在 `max-width: 768px` 时将 `.layout-body` 改为纵向布局。
- `.layout-aside` 变为全宽顶部目录；`.side-menu` 横向滚动，目录项保持可点击文本。
- `.layout-main` 全宽，移除父级 `overflow: hidden` 对内容的裁切。
- 登录配置、二维码和日志区继续按已有 `max-width: 960px` 规则单列，不改变 API handler。

### 4.3 机器人配置

- `.header-actions` 在移动端改为单列且宽度 `100%`，群选择器覆盖可用宽度。
- 页签保持顶部布局和可横向切换，不压缩文本。
- 描述区长值换行；内部表格改用同一移动卡片结构。
- 固定像素 drawer 在移动端使用 `100%` 宽度，桌面尺寸保持原值。

### 4.4 字典与用户双栏页

- 左侧树和右侧内容在移动端上下排列。
- 树区域全宽、设置受控最大高度和独立纵向滚动。
- 右侧数据使用卡片列表；桌面双栏保持不变。

## 6. 状态、权限与错误处理

- 请求仍由原页面发起；卡片组件不新增请求、不缓存数据。
- loading、empty、error 和 retry 沿用现有页面状态，不能因切换视图重复请求。
- `v-auth`、按钮显示条件、确认弹窗和危险操作 handler 原样复用。
- 展开卡片只改变本地展示状态，不写 store、Session、数据库或远端。
- 长文本使用换行和展开，不用截断代替完整数据。

## 7. 最小实现边界

- 不引入新依赖。
- 不修改 Element Plus 源码或使用全局 CSS 强行破坏所有 `el-table` sticky 行为。
- 不重构 API、store、路由或权限系统。
- 共享组件只有移动列表容器一个；字段布局使用统一 CSS class，不再创建字段 DSL、schema 或动态配置系统。
- 每个页面只增加移动卡片模板及必要的响应式样式，桌面表格原样保留。
